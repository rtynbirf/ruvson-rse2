# 04 — АРХИТЕКТУРА: как тренды ложатся в каркас Шаг 0–6

Каркас принадлежит владельцу (выработан и доказан в прогоне №2).
Внутренности — трендовый стек. Ниже — поток данных и точки решения.

```
                    config.yaml (единый пульт)
                            |
  [0 ОКРУЖЕНИЕ] environment.json ---- fs/каналы/LUFS/ключ/темпо
                            |
  [1 ЛОВИ] src/ + manifest.json ----- sha256-тождественность
                            |
  [2 МИНУС] minus/vocals.wav, minus/accompaniment.wav
        roformer (SDR 11.21) -> fallback demucs (8.04, доказан 0.9992)
                            |
  [3 ПАСПОРТ] passport.json --------- CREPE-трек f0, регистр, ключ, темпо
                            |
  [4 БИРКА] birka/<bank>/bank.json -- референсы RUVSON + эмбеддинги
                            |
  [5 СУММА] sum/vocals_ruvson.wav, sum/mix.wav
        контур A: Seed-VC SVC 44.1к (CLI, GPL-изоляция)
        контур B: OpenVoice v2 + ПЕТЛЯ КОМПЕНСАЦИИ (≤2 итер.)
        контур C: kNN-VC (retrieval, без обучения)
        сборка СУММА++: голос + аккомпанемент = АНСАМБЛЬ
                            |
  [6 СУД] judge_report.json --------- Δценты, SIM, клиппинг, LUFS -> PASS/FAIL
                            |
                      ledger.jsonl (журнал всего)
```

## Контракты файлов (жёсткие)

- environment.json: {"sample_rate", "channels", "duration_s", "lufs",
  "key_guess", "tempo_bpm", "warnings[]"}
- manifest.json: {"items":[{"url","path","bytes","sha256","match":bool}]}
- passport.json: {"f0":{"times[]","hz[]","periodicity[]","median_hz",
  "range_semitones"},"key","tempo_bpm","lufs","octave_jumps":int}
- bank.json: {"name","created","refs":[{"path","seconds","median_hz"}],
  "embeddings":{"model":"ecapa|wespeaker","dim":N},"tone_stats":{...}}
- compensation.json: {"iterations":[{"drift_cents","correction_cents"}],
  "final_drift_cents","accepted":bool}
- judge_report.json: {"delta_cents_median","secs_sim","clipping_ratio",
  "lufs","verdict":"PASS|FAIL","reasons[]"}

## Принципы, зашитые в код

1. ОБЪЕКТ БЕЗ ОКРУЖЕНИЯ = ОШИБКА: шаг 5 не запустится без паспорта и банка;
   шаг 6 — без паспорта. Дерево артефактов проверяется перед каждым шагом.
2. МИНУС = ВЫЧЕСТЬ ИНСТРУМЕНТ: vocals-стем трактуется как ниша под голос
   RUVSON; аккомпанемент не трогаем (это чужой труд — сохраняем байт-в-байт
   по качеству).
3. ОРКЕСТР = АНСАМБЛЬ = СУММА++: финальный микс собирается обратно из стемов
   (контроль корреляции сборки на шаге 2 — наследие 0.9992).
4. Тишины нет: каждый шаг пишет в ledger.jsonl успех ИЛИ причину отказа.
   Пустой шаг = баг станка, не молчание.
5. Один судья f0 — CREPE. Прочие (yin/pyin) могут лишь предсказывать,
   не судить (приборно доказано: октавные артефакты).

## Петля компенсации (наследие прогона №2 — ядро честности тона)

OpenVoice-конвертер уводит регистр: было −3.2 цента, после 2 итераций +12.6.
Петля в RSE-2 формализована:
  iter k: измерить медианный дрейф CREPE (конверт vs паспорт)
          -> сдвиг в центах -> повторный перенос
  stop: |drift| <= tolerance (по умолчанию 20 центов) ИЛИ k == 2
Порог и число итераций — в config.yaml. Всё пишется в compensation.json.

## Изоляция лицензий

собственным окружением; его код не импортируется и не линкуется — основной
пакет остаётся чистым MIT/Apache. kNN-VC/OpenVoice/RVC (MIT) — прямая
интеграция допустима.
